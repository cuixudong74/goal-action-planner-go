# goal-action-planner-go

目标导向的行动规划与执行运行时。智能体依据当前世界状态和自身目标检索行动序列；
环境在执行过程中可持续变化，行动可能失败；规划与执行结果在固定种子和相同输入
序列下**逐帧可复现**。

包结构：

| 包 | 职责 |
|---|---|
| `world` | 事实型世界状态（`key -> int64`）、条件/效果模型、版本化并发安全存储 |
| `planner` | 行动模型、目标选取/合并/冲突检测、确定性可恢复搜索 |
| `runtime` | 计划执行、执行前校验、失败重规划、资源仲裁、多智能体确定性调度、取消/超时/恢复 |

## 行动模型

```go
type Action struct {
    Name           string
    Cost           float64
    Preconditions  []world.Condition  // 全部满足才可适用/启动
    Effects        []world.Effect     // 完成时原子生效
    Postconditions []world.Condition  // 执行后由运行时校验，不满足视为"效果未达预期"
    MutexKey       string             // 同一 MutexKey 的行动不得共存于同一计划
    Resource       string             // 执行期间独占的运行时资源
    Duration       int                // 占用 ticks 数；<=1 为瞬时
}
```

条件支持 `== != < <= > >=`；效果支持 `Set` 与 `Add`。世界状态缺失的键按 0 处理。

## 规划语义

**等价路径取舍规则（总序，完全确定）**：搜索为一致代价搜索，队列键为
`(总代价升序, 行动数升序, 行动名序列字典序升序)`。因此同一输入必然得到同一计划，
与行动注册顺序、map 遍历顺序、并发调度无关。

**多目标选取与合并**：

1. 目标按 `(优先级降序, 名称升序)` 排序。
2. 依赖解析：`DependsOn` 中的目标必须存在且自身合格，该目标才合格；依赖环
   返回 `StatusDependencyCycle`（带环路径），不会无限递归。
3. 冲突检测：对合并后的条件按事实键求可行整数区间（含 `!=` 排除），区间为空
   即冲突，返回 `StatusGoalConflict` 并列出冲突的目标对与条件。
4. 合并搜索失败时逐目标独立重搜，返回 `StatusUnreachable` 及不可达目标清单。
5. 搜索受 `MaxExpansions` / `MaxDepth` 约束，超限返回 `StatusBudgetExhausted`，
   不会长时间卡死。

**规划与执行分离**：计划记录 `BaseVersion`（规划所基于的世界版本）。跨 tick 的
规划完成时若世界版本已变，计划作废（`plan-invalidated`）并基于新快照重算；每个
行动执行前都会在当前世界上重校验前置条件。

## 执行语义

- 调度器为确定性 tick 循环：每 tick 按智能体 ID 升序，各智能体至多推进一步
  （一段搜索预算或一个行动）。慢智能体只消耗自己的时间片，不阻塞他人。
- 行动效果是**原子**的：多 tick 行动被中断时不产生任何部分效果；取消/超时
  会释放其持有的全部资源，不留悬挂占用。
- 失败与偏离处理：行动失败（注入）、前置条件被破坏、效果校验不符、资源长期
  争用失败，都会从**中断点**重规划——已生效的行动效果留在世界中，新计划自然
  不会重复它们，也不会跳过仍然必需的前置条件。重规划次数受 `MaxReplans` 约束。
- 资源争用：同 tick 内 ID 小的智能体先行动，胜负确定；每次获取/拒绝/释放都
  写入事件日志，可解释、可复盘。
- 取消与恢复：`Run(ctx)` 可随时取消；再次调用 `Run` 从中断点继续，最终世界
  状态与不中断时一致（有测试保证）。

## 可复现性

- 所有迭代（事实键、目标、行动）均排序后进行；搜索队列键为全序。
- 失败注入 `FailFunc` 按 `(tick, agentID)` 固定顺序求值；`SeededFailure(seed, p)`
  在相同种子下产生相同失败序列。
- 事件日志（`runtime.Log`）在相同输入下逐字节一致，可直接做 golden 对比。

## 配置项

`planner.Options`：`MaxExpansions`（默认 100000）、`MaxDepth`（默认 64）。

`runtime.Options`：

| 字段 | 默认 | 含义 |
|---|---|---|
| `PlanBudgetPerTick` | 256 | 每智能体每 tick 的搜索扩张预算（时间片） |
| `MaxReplans` | 8 | 连续重规划上限，超出判定智能体失败 |
| `MaxResourceWaits` | 16 | 等待资源的最大 tick 数，超出按行动失败处理 |
| `MaxTicks` | 0（不限） | 整体超时 tick 数 |

## 测试

```sh
go test ./...
```

覆盖：等价路径取舍、代价优先、目标冲突（等值/区间）、目标不可达、依赖环、
计划级互斥、预算耗尽、执行偏离重规划（不重复已生效行动）、行动失败恢复、
并发资源争用（确定性胜负+无双重持有）、规划期世界变更作废、取消/恢复对齐、
超时无悬挂、慢智能体不阻塞、全链路确定性回放。
